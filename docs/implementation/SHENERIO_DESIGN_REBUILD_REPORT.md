# SHENERIO design rebuild

The complete homepage is implemented and runs locally at `http://127.0.0.1:3000`. This is a creative storefront preview. No code was pushed, no site was deployed, and no orders or subscriptions are submitted. Start with the [continuous browser walkthrough](evidence/after/SHENERIO-continuous-walkthrough.mp4), then inspect the [desktop layout](evidence/after/desktop-full.png) and [phone layout](evidence/after/phone-full.png). The full-page stills use the settled, reduced-motion layout to show all content. The uncut 48-second Chrome recording (1440 × 1000, 25 fps) shows the entrance, menu and hero handoff (0–8 s); product hover, gallery and companion switch (8–19 s); formulation tabs, origins and everyday care (19–33 s); and both scroll-linked ritual steps, Journal and closing (33–48 s). The video's capture rate is separate from the performance sample.

## Baseline and diagnosis

Inspected the pre-rebuild production site in Chrome, scrolled it with browser wheel input, and opened its navigation/product preview. Captured the [baseline browser run](evidence/before/baseline-browser.webm), [full layout](evidence/before/full.png), [phone](evidence/before/mobile.png) and [quick-view](evidence/before/quickview.png). The exact requested filename `20261108-2037-06.9224607.mp4` was not found. The local Windows recording `Screen Recording 2026-11-09 013732.mp4` corresponds to 20:37 UTC and visibly shows the rejected SHENERIO page; inspected its 17.23-second sequence as the available matching recording, without asserting binary identity. At 0–3 s, the hero leaves and the white House section scrolls into an almost static product grid; 4–7 s shows separated product pictures/prices and the premature footer; 9–11 s shows the oversized wordmark and menu; 13–16 s shows the product preview.

- **Hierarchy:** 18.25vw decorative wordmark versus 10–13px utility/caption text. The product photographs separated names/prices from the visual focus. The House layout used a rigid copy offset and a large empty middle.
- **Composition:** almost every scene was an independent rectangle. The product presentation was a staggered card grid with a 4.5% hover zoom. The site stopped after the collection, so it could not carry the brand story into formulation, provenance or ritual.
- **Motion:** the baseline had a CSS type entrance, a 3% desktop hero crop, small portrait offsets, two shallow image masks, and a modal fade/zoom. It did not have a meaningful section handoff, layered object choreography, a real alternate product view, a synchronized origin diptych, or a scroll-controlled ritual. GSAP cleanup was present; the weak transitions were principally a staging problem. The small crop played as the hero left the viewport, so much of it was hard to see.
- **Performance:** the baseline did not have a competing smooth-scroll controller, scroll-time React state, or an application wheel/touch interception. Its occasional slow frames do not establish an input problem. The large scrubbed crop and image work were candidates to measure. The comparable samples below quantify browser work; no claim is made that the screen recording alone identifies a particular rendering bottleneck.

### Scroll and loading changes

Native scrolling stays in control. ScrollTrigger owns the desktop position-linked transforms; CSS owns hover, focus, disclosure and gallery transitions. The desktop hero is one coordinated timeline; separate wrappers prevent hover and scroll from writing the same transform. GSAP setup is desktop-only and reverts on media change/unmount; breakpoint changes do not replay the desktop intro. Trigger geometry is refreshed after local fonts settle. Under 1024px, the entrance is CSS and a single visibility observer starts finite reveals; GSAP is not imported. A separate visibility boundary switches header contrast. The hero uses pre-encoded, preloaded responsive WebP sources; other media reserve their geometry and load lazily. The modal no longer applies a backdrop blur. No Lenis, input interception, custom scroll RAF, or scroll-time React rendering was added.

Visual inspection led to a thinner scrollbar gutter, more appropriate hero crops, a distinct focus-safe menu-to-dialog path, a stronger product hover image change, and a stacked gallery transition that avoids the blank frame observed in the first mobile render.

## Validation and limitations

`npm run build`, `npm run typecheck`, and `npm run test:browser` passed. Production Chrome was tested at 1440, 1024, 768, 390 and 320 CSS pixels, with a separate reduced-motion phone run. The checks covered native wheel and emulated touch input, anchor and history behaviour, menu focus and Escape, the alternate product view, gallery and accordion, keyboard ingredient tabs, the desktop ritual switch, and the preview-only Journal, newsletter and customer-care interactions. The [six Chrome runs](evidence/after/browser-qa.json) recorded zero console or page errors, zero axe violations in the scanned states, zero horizontal overflow and zero measured cumulative layout shift. The axe result does not replace testing with assistive technology.

The [baseline](evidence/before/performance.json) and [final](evidence/after/performance.json) used cold Chrome contexts on the same local server, a fixed 2,640px/2.4s scroll sample, and 4× CPU throttling with 1.6 Mbps downstream and 150 ms latency for the phone. Desktop approached a 60 Hz frame interval for most of the sample, with occasional misses and more main-thread work. On the phone, removing the GSAP import and continuous timelines improved the [first rebuild sample](evidence/after/performance-before-phone-optimization.json) from 283.3 ms to 83.2 ms at the 95th percentile. That is still behind the baseline phone's 66.8 ms, despite faster largest-content paint and fewer layout passes. The final phone sample also registered a 1.25-second startup long task; its cause was not isolated. These single machine samples cover the opening range, where the two layouts show different content. They do not establish sustained 60 fps or results on physical phones.

The local prototype uses source product names and prices (£26 / £36), reserves unconfirmed claims, and uses clearly identified concept packaging and campaign studies. The [asset register](SHENERIO_REBUILD_ASSETS.md) records image sources and treatments. Final product artwork and photographed labels, authentic SHENERIO campaign film, full Journal articles, merchant terms, and service destinations remain unavailable. Actual iOS Safari/Android hardware, screen-reader users, field performance and a controlled usability comparison against the reference sites were not tested.
